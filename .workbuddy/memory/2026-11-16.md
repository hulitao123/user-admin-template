# 2026-11-16 · 用户管理模板（F:/开发/用户管理）

## 交付
零依赖用户管理模板：Python 标准库 http.server + SQLite + 原生 JS，59 项自检全过。
`python app/server.py --demo` → http://127.0.0.1:8010 ，默认 admin/admin123（standard 档强制首登改密）。

## 目录
- app/userstore.py：建表/哈希(PBKDF2 20万)/三档策略/锁定/token_version/八道保护/审计
- app/auth.py：HMAC 签名 token（带 tv）
- app/server.py：路由 15 个接口 + 静态服务 + demo 种子
- web/{index.html,style.css,app.js}
- tests/selftest.py：59 项

## 关键设计（借鉴 Keycloak Account/Admin Console、Django staff）
- 个人中心（所有角色）：改自己显示名、改自己密码（必须验旧密码）、看自己审计
- 系统管理（仅 admin）：用户增删改、重置他人密码（临时密码，下次登录强制改）、解锁、下线、导入导出、全量审计
- 管理员在系统管理里改自己密码 → 403，强制走个人中心
- 第 8 道保护：不能修改自己的角色（原方案缺，实测会当场丢权限）
- 审计表触发器禁止 UPDATE/DELETE；old/new 存 JSON 快照

## 踩坑
- 本机 pip 走代理 502，装不上 FastAPI → 改标准库实现（也成了卖点）
- ExpCell 曾按 state 判断颜色，锁定用户的过期日期显示橙色 → 应按日期比较
- 批量导入：前端校验失败的行也要拼进「未导入」明细，否则结果对不上
- 原生 confirm 换自定义 confirmBox，Esc/Enter 用捕获阶段 stopPropagation 防止穿透到主监听

## 后续变更（同日）
- 默认口令统一为 Aa123456：初始 admin、新建用户、重置他人密码三处一致；gxp 档自动补成 Aa123456@Init（策略要求 12 位四类字符）
- 密码留空 = 按默认发；用默认密码一律强制首登改密；默认密码不受「历史 3 次不复用」限制
- GxP 体检：用户列表页自动提示通用账号（admin/root/sa 等）与「可用管理员 < 2」，文案定位为上线前待办
- 登录页移除「初始账号 admin / admin123」提示，placeholder 也不暗示账号名；启动日志仅新建库时打印初始账号
- 删除命令行解锁开关（--unlock）：无认证即可解锁 = 绕过访问控制，不符合 GxP。唯一管理员被锁只能等 15 分钟自动解，或由第二个管理员解锁 → 强化「至少两个实名管理员」
- 教训：admin 被连续试错 5 次锁 15 分钟，表象像「密码不对」，实际是锁定；verify_login 已区分禁用/锁定/过期/密码错
